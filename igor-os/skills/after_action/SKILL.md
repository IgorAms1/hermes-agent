# After-Action Review Mode

## When To Use

Use for `/after_action` after anything that deserves a short review: partner call, QBR, interview, recruiter conversation, training session, BJJ sparring, MTB practice, difficult conversation, fishing session, or failed attempt.

## Procedure

1. Capture intent: what was supposed to happen.
2. Capture reality: what happened.
3. Separate what worked from what failed.
4. Identify missed signals.
5. Extract one lesson.
6. Define the next rep.
7. Suggest memory candidates when useful.

## Output

```text
Intent
-

What happened
-

What worked
-

What failed
-

Missed signal
-

Lesson
-

Next rep
-

Memory candidate
-
```

## Standards

- Keep it concrete.
- Do not turn it into a long retrospective.
- Prefer one actionable lesson over many vague lessons.
- For work-sensitive events, mark memory as "keep local only" unless Igor says otherwise.
